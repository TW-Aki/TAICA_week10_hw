動機

為什麼要本地部署？

隱私

文件、程式碼與對話都不必離開電腦。Strata 主打 No account needed、完全本機運行。

成本

一次性硬體成本取代長期 API 帳單。本機 localhost API 可取代付費端點。

離線

沒有網路也能聊天、寫程式；模型與推論引擎都存放在本機。

但代價是：要自己處理模型下載、量化選擇、記憶體配置與速度取捨。

定義

Strata 是什麼？

Strata 是一個開源、完全在本機運行的 AI 推理引擎，同時提供桌面 App 與終端機 App。

形態

  • 桌面 App（Windows / Linux / macOS arm64）
  • 終端機 App（strata launch）
  • 開源、MIT、不需註冊帳號

主打模型

  • Qwen3.8-Flash-Next（ISTA-DASLab）
  • 量化：Q2_0、IQ2_XS、IQ3_XXS、IQ3_S
  • Coder：IQ1_M
官方原理

Strata 如何把 125B 模型塞進小顯卡？

選型

跟 Ollama / vLLM / SGLang 差在哪？

工具定位核心技術硬體門檻強項
Strata消費級跑超顯存 MoEC++ 異構分層排程、CPU/GPU 平行12–24G 顯卡 + 32–64G+ RAM單併發極致優化
Ollama輕量個人應用llama.cpp / GGUF一般 PC、Mac、甚至純 CPU一鍵上手、模型庫完整
vLLM企業級生產服務PagedAttention + Continuous Batching資料中心卡高併發吞吐
SGLangComplex Agent / 長文本RadixAttention多卡集群前綴快取、結構化解碼

簡單記：Strata 是把「放不下」的模型跑起來，Ollama 是把「放得下」的模型跑得最快。

硬體

先查記憶體，再選模型

量化光譜

  • IQ1_M / IQ2_XS / IQ3_XXS：最省記憶體，但複雜推理可能退化
  • UD-Q4_K_XL / UD-Q6_K_XL：品質與資源的平衡
  • Q8_0：品質最好，但最吃 VRAM / RAM
  • Gyro-S / Gyro-M：更省記憶體但更慢

決策流程

  • 查自己的 VRAM 與 RAM
  • 對照 docs/MODELS.md#pick-by-memory
  • 記憶體緊 → 低 bit；充裕 → 高 bit
  • 確認 GPU 在支援清單內（RTX 20/30/40/50、AMD RX 7700+ 、Apple Silicon M1+…）

MoE 模型的「總參數」不等於每次推理的計算量，但全部專家仍要放進記憶體。

安裝

三條安裝路線

A · 桌面 App

下載 Releases 安裝檔，Windows 用 .exe、Linux 用 .AppImage、macOS 用 .dmg。首次啟動會自動下載對應引擎。

B · 終端機

# Linux / macOS
curl -fsSL .../install.sh -o install.sh && sh install.sh

# Windows PowerShell
irm .../install.ps1 | iex

strata launch

C · 原始碼 / Docker

倉庫提供 Dockerfile、CMakeLists.txt、setup.py，適合要修改或特殊部署的人。

裝完請開新的終端機讓 PATH 生效，再執行 strata launch。

實作

第一次啟動與對話

桌面 App：從 GitHub Releases 下載對應平台的安裝檔（例如 `Strata-0.2.15-windows-x64-setup.exe`、`Strata-0.2.15-linux-x86_64.AppImage`、`Strata-0.2.15-macos-arm64.dmg`）。

檢查清單

  • 模型是否成功下載
  • 能否正常對話
  • 圖片輸入是否可用

常見誤區

  • 以為要註冊帳號（不用）
  • 以為只能 NVIDIA（AMD / Intel / Apple 都支援）
  • 以為任何模型都能拉（其實針對特定 MoE 調校）
串接

把 Strata 變成其他工具的後端

Strata 在本機 localhost 同時提供 OpenAI 相容與 Anthropic 相容 API，且支援圖片輸入。

strata connect

可接入：

Claude CodeCodex CLIOpenCode oh-my-pipi.devHermes AgentOpenClaw

做法：把工具的 API base URL 指向 Strata 本機位置，model 欄填 Strata 提供的模型名稱。敏感資料不必出電腦。

限制

常見問題與效能瓶頸

模型支援較窄

為壓榨特定 MoE 的效率，Strata 不像 Ollama 能隨意拉任何小模型。

記憶體與 CPU 門檻

全量專家駐留 RAM，通常要 32–64GB，且 CPU 需支援 AVX2 / AVX-512。

低量化劣化

IQ2 / Q4 等極低 bit 會讓複雜推理能力下降。

併發不是強項

針對 Batch=1 優化；若要上百人同時用，應改選 vLLM。

本地部署最大的限制不是算力，而是「模型權重放不放得下、搬得快不快」。

反思：哪個節點最常出錯？

最常出錯：draft → check

最常出錯的不是 ingest、chunk 或 index，而是 **draft 的輸出被 check 攔下來**。六個條目中失敗都集中在 `check` 節點，可有兩類： 1. **definition 太短**：草稿直接抽到一句短結論（例如「適合：不想碰終端機、只想試試看的人。」），不到 20 字，連續三輪被判 FAIL。 2. **sources / related 缺欄位**：草稿只寫了重點，忘了帶來源網址與關聯條目，讓 Wiki 變成孤立頁面。 ## 我怎麼調整檢查流程 1. 把 definition 的下限（≥20 字）明確寫進 validator，並要求 regenerate 時改挑最長的句子；仍不夠長就把主題名接在前面。 2. 把 `sources` 與 `related` 從「有就好」改成必要欄位，且 `missing` 只帶回要補的鍵，不做整段重寫，節省時間也保留原本正確的內容。 3. 把 `06_teaching_outline` 從 context 排除：它幾乎全是標題條列，會讓 definition 變成「1. 封面：…」這種大綱，而不是定義句。 4. 為六個主題各寫一組檢索詞（`TOPIC_QUERIES`），避免所有主題都命中同一篇大綱。 調整後六個條目全部通過，其中一個需要 2 輪（如 `out/run_log.md` 所示）。

我怎麼調整檢查流程

  • 把 definition 下限（≥20 字）寫進 validator
  • sources / related 改為必要欄位，missing 只回補缺失鍵
  • 把教學大綱從 context 排除，避免定義變成標題列表
  • 為六個主題各寫檢索詞（TOPIC_QUERIES）
  • 本地模板抽取可讀性有限 → 有 API key 時換真實 LLM

最大的收穫：與其相信 LLM 一次就寫對，不如把「檢查—修正」做成 graph 裡會重複執行的節點。
